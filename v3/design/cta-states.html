CTA states

Every actionable control, live. Hover, press and tab through them — this page loads the same cta.css the screens do, so what happens here is the specification. Nothing moves, nothing changes fill, nothing resizes: the label or icon takes the warm accent and the drop shadow takes the same hue, soft and restrained — warmed, not lit up.

Text button · .rbtn — 1c save / share / play again, 1d download / copy link

Hover and focus-visible: color: #FFAE68 + --shadow-glow. Press: bloom contracts, inset deepens (--shadow-press). The old opacity: .85 hover is removed.

Primary · .rbtn-primary — 1d

The 12s travelling hairline is unaffected by hover. The glow lands on the wrapper (--shadow-glow-flat, no inset) and the label warms.

Icon chip · .icon-pill — 1b home / replay / mute

The fourth chip is the persistent muted state: aria-pressed="true" holds the warm colour and glow with no pointer on it. Icons take their colour from the button (stroke: currentColor), so the same icon file serves every state.

Palette chip · .pal-pill — 1a, 1b

The chip is one target: hovering anywhere on it warms the chip and the shuffle icon. The colour dots have no hover state of their own.

Surface selector · #surface-chip — 1a armed

No hover state by design — the tiles carry a persistent selection (#383838 recess) and a hover treatment there reads as selecting. Keyboard focus warms the label only.

Timeline · #timeline-chip — 1c

Scrub state, not hover state: press the track (or tab to it) and the fill and thumb go warm with the chip glowing; release and it returns. Hovering alone gives the thumb a faint warm ring only. Implementation: add .scrubbing to the track on pointerdown, remove on window pointerup — :active and :focus-within are fallbacks.
